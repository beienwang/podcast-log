# 播客收听档案 · Podcast Log

一个纯静态的个人播客记录页：每听完一期，记一笔；页面自动把记录汇总成频道偏好、常听主题和收听节奏。

只有三件事：**记下来、看得见、带得走**。不追更、不推荐、不上传，也不需要安装任何东西。

---

## 一、它解决什么问题

播客是线性媒介，听完就过去了。一年后你大概记得「好像听过一期讲稀缺的」，但想不起是哪档节目、主播到底说了什么、当时为什么觉得好。

这份档案就是把那些容易蒸发的东西固定下来：

- **主播说了什么**——不是你的感想，是对主播叙述的复述；
- **你带走了什么**——三条以内，能复述出来的才算；
- **你偏爱什么**——用记录反推，而不是凭印象。

第二件事的副产品才是重点：当你把 20 期记录摊开，会发现自己以为喜欢的频道其实只点开过两次，而真正反复回去的是一个你从没跟人提过的节目。**记录的价值不在于攒数量，而在于让偏好变得可检验。**

## 二、怎么打开

**方式 A：直接双击**

打开 `index.html` 即可，Chrome / Edge / Safari / Firefox 都行。不联网也能用。

**方式 B：本地服务器（推荐）**

某些浏览器对 `file://` 下的 localStorage 限制较多，起个静态服务器更稳：

```bash
python -m http.server 8899 --directory .
# 浏览器访问 http://127.0.0.1:8899/
```

没有 Python 的话，任何静态服务器都可以（`npx serve`、VS Code 的 Live Server 等）。

**手机上用**：把整个文件夹放到一个静态托管上（见第八节），用手机浏览器打开；或者直接把 `index.html` 传到手机再用浏览器打开。

## 三、页面分四块，各看什么

**① 首屏统计**
四个数字：记录期数、累计时长、平均评分、频道数。下面一行是时间跨度（最早一期到最近一期）。数据为空时会是 0，属于正常。

**② 偏好频道**
按节目汇总的卡片，每张卡上有：期数、累计时长、平均分、最近一次收听、高频主题，以及一句自动生成的评语。

排序依据是「偏好指数」：

```
集数 40% ＋ 平均评分 35% ＋ 投入时长 25%
```

三项分别对应**打开频率**、**满意度**、**愿意投入的时间**。之所以不只看时长，是因为「听得最多的」不一定是「最喜欢的」——单集三小时的节目听两期，就顶得上十期短节目。

**③ 主题与节奏**
左边是标签云，字号代表出现次数，**点一下标签就能筛出相关记录**；右边是近六个月的收听柱状图，看自己是持续在听，还是集中补课。

**④ 收听记录**
卡片列表，工具栏从左到右依次是：搜索框、频道筛选、排序（最近收听 / 评分最高 / 时长最长 / 按节目分组）。

搜索会同时匹配节目名、主播、标题、标签、主播笔记、收获和金句——所以「我记得他讲过一句关于 X 的话」也能搜到。

## 四、记一笔：每个字段填什么

点右上角「＋ 记一笔」打开表单。

| 字段 | 说明 |
| --- | --- |
| 节目名称 * | 频道名，偏好按它聚合 |
| 主播 | 主播或主理人，可留空 |
| 剧集标题 * | 这一期的标题 |
| 收听日期 * | 哪天听的；不记得就填一个大致日期 |
| 时长 | 分钟数，影响累计时长与节奏图 |
| 我的评分 | 0.5–5，半星一档 |
| 主题标签 | 逗号分隔，会汇总进「常听主题」 |
| 收听链接 | 单集地址，填了之后标题可点击跳转 |
| 主播笔记 | 见下方写法 |
| 我的收获 | 一行一条，最多十条 |
| 金句 | 一句原话 |

### 主播笔记怎么写

这是整套记录里唯一需要动脑的字段。建议按三层写，三句话就够：

1. **主张**：主播想让你相信什么？
2. **论据**：他用什么材料、什么嘉宾、什么案例撑起来的？
3. **留白**：他没回答、绕过去、或者明显偏了一下的地方在哪？

关键在于**不要写你的评价**。评价留给「我的收获」。这样三个月后你还能分清「这是节目说的」和「这是我自己想的」——大部分笔记之所以没用，就是因为这两件事混在一起了。

## 五、改了、删了怎么办

卡片右下角有「编辑」和「删除」。编辑会回填全部字段，删除会二次确认，且不可撤销（删之前可以先导出备份）。

删除后如果当前筛选的频道已经空了，页面会自动把筛选清掉，不会让你卡在一个空列表里。

## 六、数据存在哪、怎么备份

- 全部数据存在**当前浏览器**的 localStorage，键名 `podcast-log.v1`。
- 不联网、不上传、没有账号、没有统计脚本。
- 页脚「导出备份」会下载一个 `podcast-log-YYYY-MM-DD.json`，里面就是全部记录。
- 换设备 / 换浏览器 / 清理浏览器数据都会丢记录，**定期导出**是唯一的保险。
- 「导入 JSON」会**覆盖**当前全部记录，导入前有确认提示。
- 「清空全部」和「载入示例数据」都在页脚，都会二次确认。

导出的 JSON 结构很简单：

```json
{
  "entries": [
    {
      "show": "节目名",
      "host": "主播",
      "episode": "单集标题",
      "date": "2026-10-30",
      "duration": 72,
      "rating": 4.5,
      "tags": ["历史", "全球化"],
      "hostNotes": "主播说了什么",
      "takeaways": ["收获一", "收获二"],
      "quote": "金句"
    }
  ]
}
```

导入时字段可以缺省：`rating` 默认 3 分、`duration` 默认 0、`date` 默认今天；`tags` 和 `takeaways` 既可以是数组，也可以是逗号 / 换行分隔的字符串。仓库里的 `import-template.json` 是一份可以直接改的模板。

## 七、几个顺手的小功能

- **深浅色主题**：右上角月亮/太阳切换，选择会被记住。
- **快捷键**：`/` 跳到搜索框，`N` 新建记录（输入框里不会误触发）。
- **打印**：直接 Ctrl/Cmd + P，会自动隐藏工具栏和按钮，只留统计与卡片。
- **手机**：窄屏下自动单列，筛选条可横向滑动。
- **无障碍**：卡片操作有 aria-label，弹窗焦点会落在节目名，Esc 关闭。

## 八、想放到网上（可选）

整个站点只有 HTML / CSS / JS 三个静态文件，丢到任何静态托管都能跑，不需要后端：GitHub Pages、Netlify、Vercel、Cloudflare Pages、对象存储都行。

**有一点必须知道**：数据存在**访问者自己的浏览器**里。别人打开你的链接，看到的是 `data.js` 里的示例数据，读不到你的记录；你在自己电脑上新增的内容，也不会出现在别人眼前。

这既是隐私上的好事，也意味着：如果你想把它当「对外展示的收听档案」，得把数据直接写进 `assets/data.js`（或让别人导入你的 JSON）。

## 九、文件结构

```
podcast-log/
├─ index.html            页面骨架
├─ assets/
│  ├─ styles.css         全部样式与深浅色变量
│  ├─ data.js            示例数据（window.SEED_EPISODES）
│  └─ app.js             统计、渲染、筛选、增删改、导入导出
├─ import-template.json  导入用的空模板
└─ README.md             你正在看的这份
```

页面自带的 14 条记录是**虚构的示例数据**（节目名是真实存在的播客，剧集标题与笔记均为演示用），页面上会提示「当前是示例数据」。你新增或导入第一条自己的记录后提示消失；想重新体验一遍，页脚的「载入示例数据」可以还原。
